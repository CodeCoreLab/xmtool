## 一、项目概述

### 1.1 项目用途

「小马远程桌面」是一个轻量的 Windows 桌面远程桌面连接管理工具。它把「连接记录」「凭据加密」「批量在线检测」「本机 RDP 服务管理」四件事收进一个 WPF 单文件程序，主要面向运维/网管/DBA 等需要长期管理多台远程主机的场景。

- 工程代号：`RemoteDesktopPlus`
- 界面品牌名：**小马远程桌面**（3 处 XAML 中出现，见 §7.1）
- 产物名：`小马远程桌面.exe`
- 定位：单机工具，不联网、不上云、无服务端

### 1.2 主要功能

| 功能 | 实现要点 | 涉及文件 |
|---|---|---|
| 连接记录增删改查 | `Connections` 表 + SQLite CRUD | `DatabaseService` / `MainViewModel.Connections` |
| 拖拽排序 | `GongSolutions.WPF.DragDrop`，事务内批量 `UPDATE SortOrder` | `MainViewModel.Connections.cs:117-145` |
| 双击直连 | `DataGrid` `MouseDoubleClick` → `ConnectItem` | `MainWindow.cs:87-98` |
| 凭据加密（双形态） | `D1$` DPAPI / `M1$` AES-256-GCM | `CryptoService` |
| 启动密码 | PBKDF2-SHA256 × 200,000 + 定时安全比较 | `LoginWindow` + `CryptoService.HashLaunchPassword` |
| 主密码（跨机器迁移） | 全量重加密 + 事务 + 失败回滚 | `CryptoService.SetMasterPassword` / `RemoveMasterPassword` |
| 批量在线检测 | 并发 TCP 探活，1.5s 超时 | `OnlineProbe` |
| 本机 RDP 服务管理 | 注册表 `fDenyTSConnections` / `PortNumber` + `netsh` 防火墙规则 | `RdpServerService` |
| 系统托盘 | WinForms `NotifyIcon`（最小化/关闭隐藏、右键菜单） | `TrayController` |
| 单实例 | `Mutex` + `NamedPipeServer` 唤醒已有窗口 | `App.OnStartup` / `StartActivationListener` |

## 二、系统架构

### 2.1 整体架构

标准 WPF MVVM 分层，**依赖方向单向**：

```
                 ┌───────────────────────────────────────────┐
                 │                App.cs                      │
                 │       组合根：装配单例、管道、托盘            │
                 └───────────────────┬───────────────────────┘
                                     │ 注入

   ┌────────────────────────────────────────────────────────────────┐
   │                        Views (WPF)                              │
   │  MainWindow / EditConnection / Login / MasterPwd / About ...   │
   │  WpfDialogService : IDialogService                             │
   │        仅 WpfDialogService 允许反向持有 View 类型                 │
   └──────────────┬─────────────────────────────────────────────────┘
                  │ 依赖
                  ▼
   ┌────────────────────────────────────────────────────────────────┐
   │                     ViewModels                                 │
   │  MainViewModel（5 个 partial 文件，共 648 行）                    │
   │  不引用任何 View 类型，仅通过 IDialogService 表达弹窗意图          │
   └──────────────┬─────────────────────────────────────────────────┘
                  │ 依赖
                  ▼
   ┌────────────────────────────────────────────────────────────────┐
   │                       Services                                 │
   │  DatabaseService · CryptoService · CredentialStore              │
   │  RdpLauncher · WindowsRdpBackend · IRdpBackend                  │
   │  OnlineProbe · RdpServerService · BackupService · TrayController│
   │  IDialogService（接口，实现方在 Views 层）                        │
   └──────────────┬─────────────────────────────────────────────────┘
                  │ 依赖
                  ▼
   ┌────────────────────────────────────────────────────────────────┐
   │                        Models                                  │
   │  ConnectionItem · ConnectionFormResult · OnlineStatus          │

   │  （无任何依赖的领域层）                                          │
   └────────────────────────────────────────────────────────────────┘
```

**分层铁律**：`Models ← Services ← ViewModels`，`Views → ViewModels`。ViewModel 不引用任何 View 类型——需要弹窗时通过 `IDialogService` 接口表达意图，具体窗口由 `WpfDialogService` 在组合根（`App.OnStartup`）里注入。这个规则是本次重构的核心成果之一（对比基线 `42c7254`，`MainViewModel` 曾直接 `new` 出 `LoginWindow` / `MasterPasswordWindow`）。

### 2.2 核心模块划分

按「职责」而非「类型」划分，共 6 个模块：

| 模块 | 目录 | 主要类型 | 是否可单测 |
|---|---|---|---|
| **组合根 & 生命周期** | `RemoteDesktopPlus/` | `App` | 部分（依赖 OS 服务） |
| **数据 & 加密** | `RemoteDesktopPlus.Services/` | `DatabaseService` `CryptoService` `BackupService` `SettingKeys` | ✅ 全部可单测（`CryptoService` / `DatabaseService` 均有测试类） |
| **RDP 交互** | `RemoteDesktopPlus.Services/` | `RdpLauncher` `IRdpBackend` `WindowsRdpBackend` `CredentialStore` | ✅ 后端可注入替身，`RdpLauncherTests` 覆盖 |
| **在线检测** | `RemoteDesktopPlus.Services/` | `OnlineProbe` | ✅ |
| **系统级操作** | `RemoteDesktopPlus.Services/` | `RdpServerService` `TrayController` | ❌ 需管理员 / 系统服务 |
| **视图层** | `RemoteDesktopPlus.Views/` `RemoteDesktopPlus.ViewModels/` `RemoteDesktopPlus.Models/` `RemoteDesktopPlus.Converters/` | `MainViewModel` `MainWindow` `WpfDialogService` 等 | `MainViewModel` ✅ / `WpfDialogService` ❌（绑定 WPF） |

### 2.3 模块间依赖关系

- **`App.cs` 是唯一同时依赖 ViewModels 与 Views 的地方**（组合根职责）。除此之外，`Views` 层不引用 `ViewModels` 之外的任何 `Services` 单例（`LoginWindow` / `MasterPasswordWindow` / `SetLaunchPasswordWindow` / `EditConnectionWindow` 仍直接调用 `DatabaseService.Instance` 与 `CryptoService.Instance`，这是**已知的分层遗留**，见 §7.1）。
- **`MainViewModel` 通过构造函数注入 3 个协作者**：`DatabaseService` / `CryptoService` / `IDialogService`。这是本次重构把 VM 从「依赖静态单例」改造成「依赖接口」的结果，使 `MainViewModelTests` 能注入 `FakeDialogService` 与临时 SQLite 库。
- **`RdpLauncher` 通过静态 `Backend` 属性注入**：默认 `WindowsRdpBackend.Instance`，测试时可替换成 Mock 后端。

### 2.4 数据流转

**一次「新建连接并保存」的完整数据流**：

```
用户点击「+ 新建」按钮
   ↓
MainViewModel.NewItem() [RelayCommand]
   ↓
_dialogs.EditConnection(null, out result)     ← 通过 IDialogService 表达意图
   ↓（WpfDialogService 在 Views 层实现）
new EditConnectionWindow()                    ← 真正的 WPF 弹窗
   ↓（用户填表 + 点确定）
ConnectionFormResult { Host, Port, UserName, Password, Remark }
   ↓
MainViewModel 构造 ConnectionItem：
    EncryptedPassword = _crypto.Encrypt(result.Password)
   ↓
CryptoService.Encrypt(plain)：
   - 有主密码 → "M1$" + AES-GCM(nonce|tag|cipher) Base64
   - 无主密码 → "D1$" + DPAPI(plain) Base64
   ↓
_db.Insert(item)                                ← DatabaseService
   ↓
SQLite: INSERT INTO Connections (Host, Port, UserName, Password, Remark, SortOrder)
        SELECT last_insert_rowid()
   ↓
Connections.Add(item)                          ← ObservableCollection，UI 自动刷新
SelectedConnection = item
```

**一次「连接」的完整数据流**：

```
用户点击「连接」按钮
   ↓
MainViewModel.Connect() [RelayCommand, CanExecute="CanConnect"]
   ↓
SaveOrUpdateForm()                              ← 表单先写回数据库
   ↓
RdpLauncher.Launch(new RdpOptions(Host, Port, UserName, Password, Width, Height, RedirectLocalDrive, LocalDriveLetter, ForceConsole))
   ↓
WindowsRdpBackend.StoreCredential("TERMSRV/<host>", user, pwd)
   ↓
CredentialStore.WriteGeneric → CredWriteW(CREDENTIAL{Type=1, TargetName, CredentialBlob=UTF16LE(pwd), Persist=2, UserName})
（blob 用完后 Marshal.WriteByte 清零 + Marshal.FreeHGlobal，避免密码残留在堆里）
   ↓
RdpLauncher.WriteRdpFile：
   %TEMP%\RemoteDesktopPlus\<host>_<port>.rdp，UTF-16LE
   内容含 full address / username / prompt for credentials:i:0 / enablecredsspsupport:i:1 /
        screen mode id:i:1 + desktopwidth / desktopheight（若有分辨率）/
        drivestoredirect:s:<letter>（若勾红盘符）/
        connect to console:i:1（若强制控制台）
   ↓
WindowsRdpBackend.StartClient(rdpPath) → Process.Start("mstsc.exe", ArgumentList={rdpPath})
   ↓（延迟 5 秒后）
后台 Task：Delete rdpPath + DeleteCredential("TERMSRV/<host>")
```

**启动流程（App.OnStartup）**：

```
1. SQLitePCL.Batteries.Init()
2. new Mutex("Local\RemoteDesktopPlusPlus.SingleInstance.Mutex")
   - 已存在 → NamedPipeClientStream("RemoteDesktopPlusPlus.SingleInstance.Activate").Connect(800ms) → Shutdown → return
3. RdpLauncher.CleanupTempFiles()              ← 清理上次残留的 .rdp 临时文件
4. DatabaseService.Instance.Initialize()       ← CREATE TABLE IF NOT EXISTS
5. WpfDialogService dialogs = new()
6. if db.HasLaunchPassword() && !new LoginWindow().ShowDialog():
       Shutdown()                              ← 5 次失败后 LoginWindow 会自动 Shutdown
7. if crypto.IsMasterPasswordConfigured() && !crypto.HasMasterKey:
       dialogs.ShowMasterPassword(Unlock)
8. MainViewModel vm = new(db, crypto, dialogs)
   MainWindow mainWindow = new(vm)
   base.MainWindow = mainWindow
   mainWindow.Show()
9. new TrayController(mainWindow)              ← 最小化/关闭隐藏到托盘
10. StartActivationListener(mainWindow)        ← 命名管道唤醒已有窗口
```

**退出流程（App.OnExit）**：`_tray?.Dispose()` → `_pipeCts?.Cancel/Dispose` → `_instanceMutex?.ReleaseMutex` → `_instanceMutex?.Dispose`。

## 四、源码讲解

### 4.1 核心入口：`App.cs`

`App` 是整个程序唯一的组合根，只做 5 件事：

1. **单实例**：`Local\RemoteDesktopPlusPlus.SingleInstance.Mutex` + 命名管道 `RemoteDesktopPlusPlus.SingleInstance.Activate`。第二个实例唤醒第一个后 `Shutdown()`。
2. **数据库初始化**：`SQLitePCL.Batteries.Init()` 必须最先执行（`Microsoft.Data.Sqlite` 底层依赖 `SQLitePCLRaw` 的 native 库，未 Init 时会抛）。然后 `DatabaseService.Instance.Initialize()` 建表。
3. **权限门禁**：依次检查启动密码（`LoginWindow`）与主密码（`MasterPasswordWindow`）。任何一个都不通过就 `Shutdown()`。
4. **装配 VM**：`new MainViewModel(db, crypto, dialogs)` → `new MainWindow(vm)`。这是**依赖注入的唯一入口**——ViewModel 不再自己 `new` 任何协作者，也不再引用任何 View 类型。
5. **托盘 + 管道监听**：`TrayController` 挂上最小化/关闭事件；`StartActivationListener` 后台循环接受命名管道连接，把窗口带到前台（`Dispatcher.Invoke` 回到 UI 线程）。

**关键代码**（`App.cs:29-84`）：

```csharp
protected override void OnStartup(StartupEventArgs e)
{
    SQLitePCL.Batteries.Init();
    _instanceMutex = new Mutex(initiallyOwned: true, MutexName, out bool createdNew);
    if (!createdNew) { /* 唤醒已有实例，退出 */ Shutdown(); return; }

    base.OnStartup(e);
    RdpLauncher.CleanupTempFiles();
    DatabaseService db = DatabaseService.Instance;
    CryptoService crypto = CryptoService.Instance;
    db.Initialize();
    WpfDialogService dialogs = new WpfDialogService();

    if (db.HasLaunchPassword() && !new LoginWindow().ShowDialog().GetValueOrDefault())
    { Shutdown(); return; }
    if (crypto.IsMasterPasswordConfigured() && !crypto.HasMasterKey)
    { dialogs.ShowMasterPassword(MasterPasswordPurpose.Unlock); }

    MainViewModel viewModel = new MainViewModel(db, crypto, dialogs);
    MainWindow mainWindow = new MainWindow(viewModel);
    base.MainWindow = mainWindow;
    mainWindow.Show();
    _tray = new TrayController(mainWindow);
    StartActivationListener(mainWindow);
}
```

### 4.2 服务层关键类

#### `DatabaseService`（`RemoteDesktopPlus.Services\DatabaseService.cs`，244 行）

- **双构造**：`Instance` 静态属性走 `AppContext.BaseDirectory\data.db`；`DatabaseService(string dbPath)` 用于测试注入临时库。
- **`ConnectionScope` 私有 struct**：把 `SqliteConnection` + 可选的 `SqliteTransaction` 打包，`CreateCommand(sql)` 会自动挂上事务。这是全项目唯一的 SQL 命令入口。
- **`[ThreadStatic]` 环境事务**：`RunInTransaction(Action)` 会把当前线程的 `_ambientConnection` / `_ambientTransaction` 设为新事务，闭包内所有 `AcquireConnection()` 都拿到同一个事务；`action` 正常返回则 `Commit`，抛异常则 `Rollback`。
- **`Initialize()`**：`CREATE TABLE IF NOT EXISTS Connections` / `Settings`（DDL 见 §6.1）。
- **`ReinitializeAfterImport()`**：导入数据后调用，重建表结构（幂等）。

#### `CryptoService`（278 行）

**密文前缀语义**（`CryptoService.cs:12`）：
- `D1$` = 当前用户 DPAPI（**机器绑定，不可跨机**）
- `M1$` = 主密码派生的 AES-256-GCM（**可跨机迁移**）

**参数常量**（`CryptoService.cs:23-31`）：

```csharp
Pbkdf2Iter = 200_000;     // PBKDF2 迭代次数
KeyBytes = 32;            // AES-256
SaltBytes = 16;           // 16 字节随机盐
NonceBytes = 12;          // AES-GCM 标准 nonce 长度
TagBytes = 16;            // 16 字节认证 tag
DpapiEntropy = UTF8("RemoteDesktopPlus.Salt.v1");   // DPAPI 附加熵
```

**AES-GCM 打包格式**（`AesGcmEncrypt` / `AesGcmDecrypt`）：`Base64(nonce | tag | cipher)`。**顺序不能变**——`Decrypt` 按前 12 字节取 nonce、中间 16 字节取 tag、剩余取密文，顺序错了直接 `CryptographicException`。

**加解密入口**（`Encrypt` / `Decrypt`）：
- `Encrypt(plain)`：有 `_masterKey` 走 `M1$`，否则走 `D1$`。
- `Decrypt(cipher)`：识别前缀；无主密码解密 `M1$` 返回空串（不抛）；识别不了前缀的老密文走 `DpapiDecrypt` 兜底；任何异常都返回空串（`CryptoService.cs:172-173` 注释：「解密失败一律返回空串，不抛出」）。

**主密码管理**：
- `IsMasterPasswordConfigured()`：检查 `master.key.verifier` 是否存在。
- `Unlock(masterPassword)`：从库读 `master.key.salt` / `master.key.verifier`，用同一 PBKDF2 派生密钥，`AesGcmDecrypt(verifier, key) == "OK"` 才算通过。
- `SetMasterPassword(newPassword, existingItems)`：**全量重加密**所有条目，包在 `_db.RunInTransaction` 里；失败时**回滚内存中的 `EncryptedPassword` 字段**（`CryptoService.cs:108-116`）并抛异常。
- `RemoveMasterPassword(existingItems)`：反向操作，全部改回 `D1$`。

**启动密码**（与主密码完全独立的两套机制）：
- `HashLaunchPassword(password, out saltB64)`：PBKDF2-SHA256 × 200,000，32 字节密钥，16 字节盐，都返回 Base64。
- `VerifyLaunchPassword(password, hashB64, saltB64)`：`CryptographicOperations.FixedTimeEquals` 定时安全比较（防时序侧信道）。

#### `CredentialStore`（149 行）

**为什么存在**：原实现用 `cmdkey.exe /generic:TERMSRV/<host> /user:<user> /pass:<pwd>`，密码进命令行参数，**任何进程都能通过 `Win32_Process.CommandLine` / 任务管理器看到**。本项目改为直接 `P/Invoke` `advapi32.dll!CredWriteW`，参数面不含密码。

**关键结构**：

```csharp
[StructLayout(LayoutKind.Sequential)]
struct CREDENTIAL {
    int Flags;
    int Type;                     // = CRED_TYPE_GENERIC = 1
    IntPtr TargetName;            // "TERMSRV/<host>"
    IntPtr Comment;
    FILETIME LastWritten;         // 4 字节对齐，不是 long，否则 x64 下后续字段偏移 4 字节
    int CredentialBlobSize;
    IntPtr CredentialBlob;        // UTF-16LE 密码字节
    int Persist;                  // = CRED_PERSIST_LOCAL_MACHINE = 2
    int AttributeCount;           // = 0
    IntPtr Attributes;
    IntPtr TargetAlias;
    IntPtr UserName;
}
```

**内存卫生**：`WriteGeneric` 用 `Marshal.AllocHGlobal` 分配 blob 指针，`finally` 里先 `Marshal.WriteByte` 逐字节清零再 `FreeHGlobal`——避免密码残留在未回收堆块里（`CredentialStore.cs:109-126`）。

#### `RdpLauncher`（169 行，静态类）

**流程**（`Launch(RdpOptions)`）：
1. 有用户名 → `Backend.StoreCredential("TERMSRV/<host>", user, pwd)`。
2. `WriteRdpFile(opt)` → `%TEMP%\RemoteDesktopPlus\<host>_<port>.rdp`（UTF-16LE）。
3. `Backend.StartClient(rdpPath)` → `mstsc.exe`。
4. 后台 `Task.Delay(5000)` 后：删 `.rdp` 文件 + 删临时凭据。

**为什么延迟 5 秒**：mstsc 读取 `.rdp` 和凭据是异步的，立刻删会失败。5 秒是经验值，见 `RdpLauncher.cs:50-51` 注释。

**`.rdp` 内容**（`BuildRdpContent`）：

```
full address:s:<host>:<port>
username:s:<user>
prompt for credentials:i:0
authentication level:i:0
enablecredsspsupport:i:1
[screen mode id:i:1 + desktopwidth + desktopheight]    ← 有分辨率时
[screen mode id:i:2]                                    ← 无分辨率时（全屏）
[drivestoredirect:s:<letter>]                            ← 勾选本地盘符时
[connect to console:i:1]                                ← 强制控制台时
```

**可注入后端**（`RdpLauncher.cs:23-36`）：`public static IRdpBackend Backend { get; set; }`，默认 `WindowsRdpBackend.Instance`。测试可替换成 Mock 后端，`RdpLauncherTests` 就是这么测的。

#### `RdpServerService`（171 行，静态类）

**注册表路径**：
- `SYSTEM\CurrentControlSet\Control\Terminal Server\WinStations\RDP-Tcp`（读/写 `PortNumber`）
- `SYSTEM\CurrentControlSet\Control\Terminal Server`（读/写 `fDenyTSConnections`，`0`=开启，`1`=关闭）

**`SetPort(int)` 流程**：
1. 校验 1-65535。
2. 读旧端口，写新端口到注册表。
3. `RemoveOurFirewallRules(newPort)` 清理除新端口外的所有本项目规则。
4. 若旧端口 != 新端口：额外删旧端口规则。
5. `AddFirewallRule(newPort)`：`netsh advfirewall firewall add rule name=RemoteDesktopPlus-RDP-<port> dir=in action=allow protocol=TCP localport=<port>`。

**`RemoveOurFirewallRules` 实现细节**：用 `powershell.exe` 查 `Get-NetFirewallRule -DisplayName 'RemoteDesktopPlus-RDP-*'`，把规则名逐个用 `netsh` 删。这是**已知性能坑**（见 §7.2）。

#### `OnlineProbe`（24 行）

极简：`TcpClient.ConnectAsync(host, port, cts.Token)`，超时 1.5s，异常一律返回 `false`。

#### `BackupService`（53 行）

- `Export(targetPath)`：`FileStream(Read, ReadWrite)` + `CopyTo`——支持库正在被写时导出。
- `Import(sourcePath)`：**危险操作，带回滚**——先 `Copy(data.db, data.db.bak)` → `GC.Collect + SqliteConnection.ClearAllPools` → `Copy(source, data.db)` → `ReinitializeAfterImport`；任何一步失败把 `data.db.bak` 复制回来。

## 六、数据库结构及外部服务依赖说明

### 6.1 数据库结构

### 6.2 凭据加密方案

**两种密文形态**（`CryptoService`）：

| 前缀 | 算法 | 密钥来源 | 可跨机 | 用途 |
|---|---|---|---|---|
| `D1$` | DPAPI（`DataProtectionScope.CurrentUser`） | Windows 系统 | ❌ 机器绑定 | 默认形态；主密码未配置时 |
| `M1$` | AES-256-GCM | 主密码 PBKDF2-SHA256 × 200,000 | ✅ 可迁移 | 主密码配置后 |

**AES-GCM 打包格式**：`Base64(nonce[12] | tag[16] | cipher[N])`。顺序不能变（`CryptoService.cs:239-244` 注释）。

**启动密码哈希**：PBKDF2-SHA256 × 200,000，32 字节密钥，16 字节盐。与主密码**完全独立**——启动密码保护「能否打开程序」，主密码保护「能否解密连接记录」。

**Windows 凭据管理器**：`CredWriteW`（`advapi32.dll`），`Type=CRED_TYPE_GENERIC=1`，`TargetName="TERMSRV/<host>"`，`Persist=CRED_PERSIST_LOCAL_MACHINE=2`。mstsc 只认这个前缀。

### 6.3 外部服务依赖

| 服务 | 用途 | 是否必需 | 失败后果 |
|---|---|---|---|
| Windows 远程桌面客户端 `mstsc.exe` | 拉起远程会话 | 必需 | 「连接」按钮无效 |
| `advapi32.dll!CredWriteW` / `CredDeleteW` | 写入/删除系统凭据 | 必需 | 连接失败（mstsc 无凭据） |
| `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server` | 注册表读写（开关 RDP / 改端口） | 仅「本机远程桌面」页签 | `ToggleRemote` / `ChangePort` 抛异常，需管理员权限 |
| `netsh.exe` | 增删防火墙入站规则 | 仅「修改端口」时 | 新端口可能被防火墙拦截 |
| `powershell.exe` | 查询 `RemoteDesktopPlus-RDP-*` 规则名 | 仅「修改端口」时 | 旧规则未清理，残留防火墙规则 |
| SQLite native 库（`e_sqlite3.dll`） | 数据库读写 | 必需 | 程序无法启动 |
| 命名管道 `RemoteDesktopPlusPlus.SingleInstance.Activate` | 单实例唤醒 | 可选 | 多开时新实例直接退出（无唤醒） |
| 注册表 `HKEY_CLASSES_ROOT` 等 | WPF 内部 | 必需 | 无 |

**权限要求**：「本机远程桌面」页签（开关 RDP、改端口、加防火墙规则）需要**以管理员身份运行**。权限不足时 `RdpServerService.SetRemoteEnabled` / `SetPort` 抛 `InvalidOperationException`，UI 弹错误消息框而非静默失败。

**网络依赖**：程序自身**不联网**（不拉任何远程数据）。在线检测只连用户自己填的 `Host:Port`。

## 七、已知问题、待办事项与开发注意事项

### 7.1 已知问题（诚实清单）

#### P0：无

本次重构已把 P0 全清（`cmdkey.exe /pass:` 明文命令行已替换为 `CredWriteW`，见 `CredentialStore.cs`）。

#### P1：分层遗留

**现象**：4 个对话框（`LoginWindow` / `MasterPasswordWindow` / `SetLaunchPasswordWindow` / `EditConnectionWindow`）**直接调用 `DatabaseService.Instance` 与 `CryptoService.Instance` 静态单例**，而非通过构造函数注入。

**影响**：这些窗口无法在测试里独立观察（`WpfDialogService` 因此也**没有测试覆盖**）。

**修复方向**：把这 4 个窗口的构造函数改成接收依赖，或由 `WpfDialogService` 统一注入。工作量约半天。

#### P1：DPAPI 跨机器兼容未实测

**现象**：`D1$` 密文是机器绑定的，从机器 A 导出到 B 无法解密。这是**原设计**，未改动。

**未做**：未用第二台 Windows 实测跨机迁移。真实跨机迁移必须走主密码（`M1$`）。

#### P2：`BackupService.Import` 有 GC 抖动

**现象**：`Import` 里 `GC.Collect()` + `GC.WaitForPendingFinalizers()` + `SqliteConnection.ClearAllPools()`——这是必要的（释放当前连接池里所有对 `data.db` 的锁），但会导致一次明显卡顿。

**是否修**：不建议改。改动风险 > 收益。

#### P2：`MainWindow` 双密码控件反模式

**现象**：`PasswordBox PwdBox` + `TextBox PlainPwdBox` 叠在同一位置，通过 `Visibility` 切换。这是 WPF `PasswordBox` 无法双向绑定的历史反模式。

**修复方向**：可引入 `SecureString` 包装的属性，或改成 `TextBox` 显式显隐（牺牲安全性换简洁）。不建议改——当前实现行为正确。

#### P2：`RdpServerService.RemoveOurFirewallRules` 每次启动 `powershell.exe`

**现象**：`SetPort` 会拉起一次 `powershell.exe` 查规则名，性能约 500ms。

**是否修**：可用 `Get-NetFirewallRule` 的 .NET 等价（`Microsoft.Windows.NETSdk.Bricks.Desktop` 或 `NetSecurity` 模块），但工作量大且不影响功能。

#### P3：品牌名「小马远程桌面」残留

**现象**：`Views\MainWindow.xaml:235` 与 `Views\AboutWindow.xaml:21` 及 `Views\LoginWindow.xaml:2` 共 3 处硬编码品牌名。**这是原作者的遗留**，非本次重构引入。

**是否修**：如需品牌重命名，全局搜索替换即可（含 `TrayController` 里的 `Text = "小马远程桌面"`）。

#### P3：缺少集成测试

**现象**：当前测试均为单元测试，无端到端集成测试（例如「启动 → 新建 → 连接 → 关闭」全流程）。

**是否修**：`MainViewModelTests` 已覆盖 VM 全 API，集成测试收益有限，暂不做。

### 7.3 开发注意事项（铁律）

1. **行尾统一 LF**：`.gitattributes` 已配置 `eol=lf`。改动任何文本文件时用 LF 保存；IDE 里设置 `Insert Final Newline = true`。

2. **勿动 `SQLitePCL.Batteries.Init()` 的位置**：必须在 `OnStartup` 首行调用。放在 `App.xaml` 的 `StartupUri` 之前也不行——那时 native 库还没加载。

3. **勿从反编译源码拷贝 `[GeneratedCode]` 手写属性**：`7afdefa` 之前的版本里那些手写属性是反编译产物，与源生成器产出的会冲突 CS0102。项目现在依赖源生成器，`MainViewModel` / `ConnectionItem` 只有字段声明。

4. **`ParseResolution` 与 `BuildRdpContent` 的「非正尺寸即全屏」约定必须一致**：两者都有测试，改动任一必须跑 `ParseResolutionTests` + `RdpLauncherTests`。

5. **`DatabaseService.RunInTransaction` 语义**：闭包内所有 `AcquireConnection` 都拿到同一个事务。不要在闭包里调 `RunInTransaction`（会早退并跳过事务）。

6. **`CryptoService.Decrypt` 的容错约定**：任何解密失败都返回空串，不抛异常。调用方**不能**依赖抛异常来判断密文损坏——要靠空串判断。

7. **`[ThreadStatic]` 事务**：不要在后台线程里调 `RunInTransaction` 后立即 `Task.Run` 内层数据库操作——内层拿不到外层事务。如需跨线程事务，改用显式参数传递 `SqliteConnection`。

8. **`PasswordBox` 反模式**：`MainWindow.PwdBox` 与 `EditConnectionWindow.PwdBox` 都用 `_suppressPwdChanged` 布尔量抑制双向同步的回环。改动这两个文件时必须保持此约定。

9. **`RdpLauncher.Backend` 是可替换的**：测试时可 `RdpLauncher.Backend = new MockBackend()`；生产代码不要动这个静态属性。

10. **发布后清理**：`dotnet publish` 完成后 `publish_final/data.db` 应删除（冒烟验证会生成，不能带进发布包）。本次已删除，产物 12 文件 / 2.54 MB。

11. **管理员权限**：「本机远程桌面」页签的操作需管理员权限。测试这些功能请用管理员身份的 PowerShell 启动程序。

12. **测试工程隔离**：`tests/` 在 `RemoteDesktopPlus.csproj` 里显式排除。新增测试文件时确认路径以 `tests/` 开头；新增主项目文件不要放到 `tests/` 里。

13. **提交消息规范**：本项目用 `Step<N>: <摘要>` / `Hygiene: <摘要>` / `docs: <摘要>` 三类前缀。见 `git log` 历史。
