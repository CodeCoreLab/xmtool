## 2. 架构潜在问题（按优先级）

### 🟠 P1-1 对话框层直连静态单例（测试盲区）

- **位置**：`Views\LoginWindow.cs:47-49`、`Views\MasterPasswordWindow.cs:22,70-87`、`Views\SetLaunchPasswordWindow.cs:25-55`、`Views\EditConnectionWindow.cs:89`
- **问题**：4 个窗口直接调 `DatabaseService.Instance` / `CryptoService.Instance`，导致 `WpfDialogService`（7 个方法的实现）**零测试覆盖**——密码安全相关的解锁/设密路径是全项目最敏感逻辑，恰好在盲区。
- **建议**：窗口构造函数收依赖（`CryptoService` + `DatabaseService`），由 `WpfDialogService` 传入；工作量 ~0.5 天（交接文档已列，维持 P1 判定）。

### 🟠 P1-2 全项目零日志，30+ 处空 catch

- **位置**（关键几处）：`App.cs:41-50,102-117`、`RdpLauncher.cs:62-64,86-89,145-167`、`RdpServerService.cs:30-32,46-48,111-145,162-169`、`BackupService.cs:47-49`
- **问题**：**最危险的一处是 `BackupService.Import` 的回滚分支**（`BackupService.cs:36-50`）——回滚本身失败时静默吞掉，用户以为导入失败可恢复，实际 `data.db` 已被覆盖且备份可能未还原。其余空 catch 分布在启动/清理/防火墙路径，失败后无任何痕迹，排障只能靠"重现"。
- **建议**：引入轻量文件日志（`Microsoft.Extensions.Logging` 或自写 100 行滚动 logger，落 `%LOCALAPPDATA%\RemoteDesktopPlus\logs\`）；空 catch 至少改成 `Log.Debug(ex, "...")`。**回滚失败分支必须升级为 `Log.Error` + 下次启动时向用户提示"上次导入回滚失败，数据可能异常"**。工作量 ~1 天。

### 🟠 P1-3 服务层可测性割裂：一半静态、一半可注入

- **位置**：`RdpLauncher.cs`、`OnlineProbe.cs`、`BackupService.cs`、`RdpServerService.cs` 全静态；`MainViewModel.Connections.cs:113`（OnlineProbe）、`SecuritySettings.cs:41`（BackupService）、`Connect.cs:25`（RdpLauncher）为 VM 直调点
- **问题**：`MainViewModel` 三个协作者走构造注入，另四个服务却硬引静态类。VM 测试无法替身（如 `ScanOnlineAsync` 测试会真发 TCP）。`RdpLauncher.Backend` 虽可换，但静态可变全局状态在并行测试下有串扰风险。
- **建议**：不必一次性大改——按"改哪块抽哪块"推进：先抽 `IRdpLauncher`（VM 连接主路径，收益最大），其余三个保持静态但把副作用收敛到单一入口。

### 🟡 P2-4 明文密码以托管 string 全程流转

- **位置**：`MainViewModel.Password`（`MainViewModel.cs:50`）、`RdpLauncher.RdpOptions.Password`（`RdpLauncher.cs:21`）、`ConnectionFormResult.Password`（`ConnectionFormResult.cs:80`）
- **问题**：托管 string 不可主动清零，明文在 LOH/Gen0 残留至 GC。对比：`CredentialStore` 的非托管 blob 已做清零（A4）——**安全标准在同一进程内不一致**。
- **建议**：彻底改 `SecureString`/`char[]` 改动面大（PasswordBox 反模式叠加）；务实方案是**收敛明文 string 的生命周期**——`Connect()` 内用完即置 `Password = string.Empty`，不做全链路改造。交接文档 P2 判定合理，维持。

### 🟡 P2-5 全量重加密写放大

- **位置**：`CryptoService.cs:103` 与 `CryptoService.cs:143`（`_db.Update(entry.Item)`）
- **问题**：改主密码时每条连接重写全部 7 列，实际只改 `Password` 1 列。N 大时事务体积膨胀、journal 增大。
- **建议**：`DatabaseService` 增加 `UpdatePasswordColumn(long id, string cipher)` 单列 UPDATE，重加密循环改调它。~15 行。

### 🟡 P2-6 `BackupService.Export` 非事务一致快照

- **位置**：`BackupService.cs:9-14`
- **问题**：`FileShare.ReadWrite` 直接拷 `data.db`——拷贝瞬间若 SQLite 事务进行中（如用户正在拖拽排序），备份文件可能"半新半旧"，恢复后损坏。
- **建议**：改用 `VACUUM INTO ?`（SQLite 3.27+，单条 SQL，自动保证一致快照），回退保留现有文件拷贝。~10 行。

### 🟡 P2-7 依赖治理：libs/ 双版本 DLL 并存

- **位置**：`libs\CommunityToolkit.Mvvm.dll` 与 `libs\CommunityToolkit.Mvvm.8.3.2.dll` 同时在仓库（Glob 证据），csproj 引用的是前者
- **问题**：无法确认前者版本；无 NuGet restore 校验，升级只能手换 DLL。
- **建议**：删除未引用的 `CommunityToolkit.Mvvm.8.3.2.dll`；给保留 DLL 写版本备注（README 或 .csproj 注释）。

## 3. 性能瓶颈与改进建议

> 结论：本应用为单机小数据量工具（几百条连接、SQLite、毫秒级 AES），**不存在用户可感知的热点**。以下按「影响 × 成本」排序，仅第 1 项建议本迭代修。

| 优先级 | 瓶颈 | 代码位置 | 影响 | 成本 | 建议 |
|---|---|---|---|---|---|
| 🟠 P1 | **`ScanOnlineAsync` 无并发上限**：`Task.WhenAll` 对全部连接同时发起 TCP 探活 | `MainViewModel.Connections.cs:107-115` | 连接数达数百时瞬时 socket 风暴（临时端口/防火墙压力）；且扫描期间按钮不禁用，可重复触发叠加 | ~10 行 | `SemaphoreSlim(20)` 限流 + `IsScanning` 状态位禁用按钮（`[NotifyCanExecuteChangedFor]`） |

| 🟡 P2 | 重加密全字段 UPDATE 写放大 | `CryptoService.cs:103,143` | 与 P2-5 同源；N 大时主密码切换变慢 | ~15 行 | 见 P2-5 `UpdatePasswordColumn` |

## 4. 扩展点识别与接口设计建议

> 判定逻辑：按「未来最可能发生的需求」倒推。管理多台主机的工具，最先发生的三件事是：①记录字段不够用（分组/标签/最后连接时间）→ 需要 schema 迁移；②想从旧版本/别的工具导入 → 需要格式抽象；③想连 SSH/VNC → 需要协议抽象。

### 🟠 E1 Schema 版本迁移机制（最优先，其余扩展的地基）

- **位置**：`DatabaseService.Initialize()`（`DatabaseService.cs:74-79`）
- **职责**：任何表结构演进的安全通道。当前 `CREATE TABLE IF NOT EXISTS` 无法承载"给 Connections 加列"这类变更——老库不会自动升级。
- **设计**：

```csharp
// DatabaseService 内新增
private static readonly (string Version, Action<SqliteConnection> Apply)[] Migrations = {
    ("2", c => c.ExecuteNonQuery("ALTER TABLE Connections ADD COLUMN Group TEXT NOT NULL DEFAULT ''")),
    // 追加式扩展，永不改历史项
};

public void Initialize()
{
    /* 现有 CREATE TABLE IF NOT EXISTS ... */
    int current = int.Parse(GetSetting("schema.version") ?? "1");
    foreach (var (ver, apply) in Migrations.Where(m => int.Parse(m.Version) > current))
        RunInTransaction(() => { apply(conn); SetSetting("schema.version", ver); });
}
```

- **扩展方式**：新迁移 = 数组里追加一个元组，不改旧代码。

### 🟠 E2 数据模型扩展列（与 E1 配套）

- **位置**：`ConnectionItem.cs`（`ConnectionItem.cs:14-39`）+ `Connections` 表 DDL（`DatabaseService.cs:77`）+ `LoadAll/Insert/Update`（`DatabaseService.cs:92-142`）
- **职责**：承载后续迭代大概率出现的需求——**分组/标签**（服务器多后筛选）、**最后连接时间**（常用排序）、**协议类型**（配合 E5）。
- **设计**：`Group TEXT`、`LastConnectedAt INTEGER`（Unix 秒）、`Protocol TEXT DEFAULT 'rdp'` 三列一次到位，避免三次迁移。
- **扩展方式**：走 E1 迁移管线；`ConnectionItem` 加 `[ObservableProperty]` 字段；`Connect()` 成功后回写 `LastConnectedAt`。

### 🟡 E3 导入导出格式抽象

- **位置**：`BackupService.cs`（全静态，9-52 行）
- **职责**：当前只支持"整库 .db 文件直拷"。抽接口后可扩展加密 JSON 导出（跨版本安全）、合并式导入（不覆盖现有记录）。
- **设计**：

```csharp
public interface IBackupFormat
{
    string FormatId { get; }                       // "dbfile" / "encjson"
    void Export(string targetPath, DatabaseService db);
    void Import(string sourcePath, DatabaseService db);
}
```

- **扩展方式**：现有实现落成 `DbFileBackupFormat`；新格式实现接口后在 `MainViewModel.ExportData/ImportData`（`SecuritySettings.cs:32-75`）按扩展名分发。**注意：Import 前必须校验格式头，拒绝非本程序库文件**（当前版本导入任意 .db 无校验，属顺带发现的数据安全隐患）。

### 🟡 E4 选项持久化泛型化

- **位置**：`MainViewModel.cs:158-243`（`LoadOptions` + 4 个 `OnXxxChanged`）+ `SettingKeys.cs`
- **职责**：当前每加一个选项要动 **4 处**（字段、`OnXxxChanged`、`SettingKeys` 常量、`LoadOptions` 读取+校验）。抽 `ISettingsStore`（`Get<T>(key)` / `Set<T>(key, value)`）后收敛为 1 处字段声明 + `[ObservableProperty]` 上标注 Key 特性或集中注册表。
- **扩展方式**：新选项 = 1 个属性 + 1 行注册；`_suppressOptionSave` 模式保留（交接文档铁律 1）。

### 🟡 E5 协议抽象（IRdpLauncher 实例化 + 协议字段）

- **位置**：`RdpLauncher.cs:19-21`（静态类 + `RdpOptions`）+ `MainViewModel.Connect.cs:25` / `Connections.cs:32`（两处调用点）
- **职责**：为将来 SSH/VNC/Telnet 留通道。两步走：
  1. 先做**实例化**（纯重构）：抽 `IRdpLauncher { void Launch(RdpOptions opt); void ClearCredential(string host); }`，现有逻辑移入 `RdpLauncher : IRdpLauncher`，`App.OnStartup` 构造注入 VM——同时解决 P1-3 中最影响测试的静态依赖。
  2. 再加**协议字段**（纯扩展）：`RdpOptions` 加 `Protocol Protocol`，`IRdpLauncher` 实现内按协议选 `IRdpBackend`（`IRdpBackend.cs` 已是天然插槽）。
- **扩展方式**：新协议 = 新 `IRdpBackend` 实现 + Launch 分派一行。

### 🔵 E6 URI Scheme / 命令行直连

- **位置**：`App.OnStartup`（`App.cs:29`）——当前完全忽略 `e.Args`
- **职责**：`rdp++://connect?host=x&port=3389` 或 `小马远程桌面.exe <host>` 启动即连，便于与浏览器/其他工具集成。
- **扩展方式**：`OnStartup` 解析 `e.Args`，非空则装配完 VM 后调 `vm.ConnectItem(host, port)`；URI 注册走安装脚本（HKCU，无需管理员）。

### 🔵 E7 活动日志钩子（与 P1-2 日志基建同批落地）

- **位置**：`MainViewModel.Connect()`（`Connect.cs:15-26`）、`RdpLauncher.Launch`、`BackupService.Export/Import`
- **职责**：连接成功/失败、导入导出等安全敏感事件留痕（本地文件，仅本机可读）。
- **扩展方式**：`IActivityLog { void Write(string action, string target, bool ok); }`，默认空实现，后续可接 Windows 事件日志。

### 🔵 E8 托盘菜单数据源化

- **位置**：`TrayController.cs:40-46`（硬编码 3 项）
- **职责**：右键菜单加"快速连接"子菜单（最近连接 Top 5，数据源用 E2 的 `LastConnectedAt`）。
- **扩展方式**：`TrayController` 构造函数注入菜单项提供者（`Func<IReadOnlyList<ConnectionItem>>`）。
